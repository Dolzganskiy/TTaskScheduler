# TTaskScheduler

**TTaskScheduler** — библиотека на **C++23** для построения и выполнения графа зависимых вычислений.  
Каждая задача представляется узлом ориентированного ациклического графа, а результат одной задачи можно передать другой через объект `TFuture`.

В репозитории также находится демонстрационное приложение, которое определяет местоположение пользователя, получает текущую погоду и подбирает подходящие места поблизости.

## Возможности

### Библиотека планировщика

- добавление задач с произвольным количеством аргументов;
- поддержка функций, лямбда-выражений и указателей на методы классов;
- построение зависимостей между задачами через `TFuture`;
- ленивое вычисление только необходимых узлов графа;
- выполнение всех зарегистрированных задач через `ExecuteAll`;
- построение последовательных цепочек с помощью `Apply`;
- хранение результатов разных типов через собственный type erasure;
- передача аргументов с использованием variadic templates и perfect forwarding;
- получение результата по значению либо по ссылке;
- обработка задач, возвращающих `void`;
- защита от повторного прямого перемещения результата.

### Демонстрационное приложение

Приложение строит вычислительный конвейер из нескольких зависимых задач:

1. определяет координаты пользователя по IP-адресу;
2. получает текущую температуру и погодные условия;
3. выбирает категорию мест с учётом погоды;
4. ищет ближайшие заведения или достопримечательности;
5. выводит итоговую рекомендацию.

## Пример графа вычислений

```mermaid
flowchart LR
    A[Определение координат] --> B[Получение погоды]
    A --> C[Поиск мест]
    B --> C
    B --> D[Формирование результата]
    C --> D
```

Задача выполняется только один раз. Если её результат требуется нескольким зависимым узлам, они используют уже вычисленное значение.

## Пример использования библиотеки

```cpp
#include "TTaskScheduler.h"

#include <iostream>
#include <string>

int main() {
    TTaskScheduler scheduler;

    auto base = scheduler.Add([] {
        return 10;
    });

    auto doubled = scheduler.Add(
        [](const int& value) {
            return value * 2;
        },
        base.GetFutureResult<const int&>()
    );

    auto message = doubled.Apply(
        [](int& value) {
            return std::string("Result: ") + std::to_string(value);
        }
    );

    std::cout << message.GetResultSync() << '\n';
}
```

Результат:

```text
Result: 20
```

## Публичный интерфейс

### `TTaskScheduler`

```cpp
template<typename Task, typename... Args>
auto Add(Task&& task, Args&&... args);

void ExecuteAll();
```

#### `Add`

Регистрирует новую задачу вместе с её аргументами и возвращает типизированный объект `TTask<Result>`.

Аргументами могут быть:

- обычные значения;
- ссылки;
- результаты других задач в виде `TFuture`;
- объекты классов при вызове указателя на метод.

#### `ExecuteAll`

Выполняет все задачи, зарегистрированные непосредственно в планировщике. Уже вычисленные узлы повторно не запускаются.

### `TTask<T>`

```cpp
T GetResultSync();

template<typename Result = T>
TFuture<Result> GetFutureResult();

template<typename NewTask>
auto Apply(NewTask&& task);
```

#### `GetResultSync`

Синхронно возвращает результат задачи. Если задача ещё не выполнялась, сначала вычисляет её вместе с необходимыми зависимостями.

#### `GetFutureResult`

Создаёт объект, через который результат задачи можно использовать как аргумент другого вычисления.

Для многократного чтения без перемещения удобно запрашивать ссылочный тип:

```cpp
auto future = task.GetFutureResult<const Result&>();
```

#### `Apply`

Создаёт новую задачу, которая получает результат предыдущей и продолжает цепочку вычислений:

```cpp
auto transformed = task.Apply([](Result& value) {
    return Transform(value);
});
```

### `TFuture<T>`

`TFuture` хранит ссылку на узел графа и инициирует его вычисление при необходимости. Получение результата по значению через `Get` допускает одно прямое перемещение; повторная попытка приводит к исключению.

## Внутреннее устройство

```text
TTaskScheduler
│
├── NodeBase
│   ├── TaskNode<Task, Args...>
│   └── ChainNode<PrevType, NewTask>
│
├── TTask<T>
├── TFuture<T>
├── Any
├── Invoke
└── Node<T, Args...>
```

### `NodeBase`

Полиморфная основа узла графа. Предоставляет общий интерфейс выполнения и доступа к type-erased результату.

### `TaskNode`

Хранит callable-объект, его аргументы, состояние выполнения и результат. Для раскрытия произвольного числа аргументов используются:

- variadic templates;
- `std::index_sequence`;
- perfect forwarding;
- compile-time определение возвращаемого типа.

### `ChainNode`

Представляет узел, созданный через `Apply`. Перед запуском он вычисляет предыдущую задачу и передаёт её результат следующему callable-объекту.

### `Any`

Собственная упрощённая реализация type erasure. Результат хранится за абстрактным базовым классом, а проверка типа выполняется при получении значения.

### `Invoke`

Универсальная функция вызова, поддерживающая обычные callable-объекты и указатели на методы классов.

### `Node<T, Args...>`

Рекурсивная структура, похожая на упрощённый `std::tuple`. Используется для хранения произвольного числа аргументов задачи.

## Демонстрационное приложение

Пример приложения показывает использование планировщика в реальном сценарии с несколькими внешними сервисами.

| Компонент | Назначение |
|---|---|
| `Geoposition` | получение координат по IP-адресу |
| `Forecast` | получение текущей погоды через Open-Meteo |
| `Places` | поиск ближайших мест через Foursquare Places |
| `App` | вывод погоды и рекомендаций |
| `TTaskScheduler` | связывание этапов в единый граф |

Ошибки сетевых запросов передаются между этапами через `std::expected`.

## Сборка

```bash
git clone <repository-url>
cd TTaskScheduler

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Запуск приложения:

```bash
./build/labwork9
```

Запуск тестов:

```bash
ctest --test-dir build --output-on-failure
```

Для первой конфигурации проекта требуется подключение к интернету, поскольку CMake загружает внешние зависимости.
